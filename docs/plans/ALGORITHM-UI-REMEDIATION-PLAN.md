# ScoreFollow 算法与 UI 整改执行计划

## 目标

把当前 synpdf rev.194 的移植版本提升为可重复、可诊断、可校正的谱面跟随工具。验收以真实 PDF 为准，不以单张合成谱的通过作为唯一标准。

## 阶段 1：建立识别基准集

1. 收集至少 12 份 PDF：单谱表、钢琴双谱表、三谱表、跨页、横向缩放、低对比度扫描、带反复/双小节线、含歌词和密集符干的谱面。
2. 为每页保存人工标注 JSON：系统框 `x1/x2/y1/y2`、每条小节线 x、有效小节数量。
3. 编写 Node 回归脚本，逐页运行 `analyzePage`，输出 precision、recall、平均 x 偏差、系统框 IoU 和异常页清单。
4. 固定渲染宽度、PDF.js 版本和参数快照，避免浏览器缩放造成假差异。

验收：每次改算法都能生成同一格式的机器结果和差异报告；合成谱、Secret Garden 真谱继续通过。

## 阶段 2：提升系统与小节识别

1. 将 `synpdf-legacy.ts` 的匿名变量算法拆成可测试函数：灰度投影、谱线间距估计、系统候选、垂直线候选、候选合并。
2. 小节线检测采用多证据评分：垂直连续性、暗像素比例、左右邻域亮度对比、与相邻谱线组的交集比例。
3. 对候选 x 做局部峰值合并，合并半径使用 `spatium` 的比例而不是固定像素。
4. 区分单线、双线、终止线和符干：要求候选在多数谱线间连续，并用左右上下窗口排除只穿过局部音符的竖线。
5. 对每个系统输出置信度和拒绝原因；低置信度结果在 UI 中显示为黄色，而不是静默当作正确。
6. 处理边界：系统左右边界只作为小节端点，不计入内部小节线；空系统、窄系统和只有一条候选线的系统不崩溃。
7. 保留 `legacyOpt` 兼容参数，但增加一个稳定的 `analysisProfile`，允许“快速/精确/扫描谱”预设。

验收：基准集上内部小节线 precision >= 98%，recall >= 97%，平均 x 偏差 <= 1.5px（统一渲染宽度）；低置信度页可解释。

## 阶段 3：分析数据模型与同步正确性

1. 给 `PageAnalysis` 增加 `pageNumber`、`confidence`、候选诊断和算法版本。
2. 缓存键包含页号、渲染尺寸、所有影响识别的参数和算法版本，参数变化必须重新分析。
3. 重新渲染页面时保留合法 timing；若小节数量变化，按原小节索引截断并给出状态提示。
4. `buildMeasures` 使用系统索引而非对象查找，并过滤非递增或零宽小节。
5. 点击命中使用独立 x/y 缩放；时间映射严格限制在命中的系统和小节内。
6. timing JSON 加入 PDF 文件名、页数、分析版本和小节数量，载入时校验并报告不兼容。

验收：改参数不会串用旧缓存；翻页、缩放、重新分析、载入 timing 后光标和点击 seek 均稳定。

## 阶段 4：人工校正工作流

1. 增加“校正模式”：点击错误小节线可选中，拖动 x 调整；双击新增，Delete 删除。
2. 校正仅作用于当前页，并以 `manualBarsByPage` 叠加在自动结果上，不修改原始识别结果。
3. 增加“恢复自动识别”和“应用到同类页面”命令。
4. timing 保存时写入校正信息，载入时先校验页尺寸和算法版本。
5. 录入键盘快捷键和撤销/重做栈；所有校正操作都显示状态反馈。

验收：错误小节线可在 3 次操作内修正，刷新/导出/载入后位置保持一致，恢复自动识别可完全撤销人工层。

## 阶段 5：UI 整理

1. 将页面分为顶部文件区、播放控制区、分析状态区、谱面区和高级设置区。
2. 移除 JSX 内联样式和内嵌 `<style>`，统一使用 `page.module.css`；按钮、输入框、焦点态和禁用态统一。
3. 移动端工具栏允许横向滚动；谱面保持稳定宽高比，不因控件换行改变覆盖坐标。
4. 高级参数按“识别 / 系统 / 调试”分组，增加当前 preset 和恢复默认值。
5. 分析状态显示页码、系统数、小节数、置信度和耗时；异常时提供可读错误。
6. 覆盖层提供系统框、小节线、当前光标、低置信度标记四种独立开关，并保证颜色对比度。

验收：桌面 1280px、平板 768px、手机 390px 截图无重叠；上传、播放、TAP、seek、保存/载入 timing 全流程可用。

## 阶段 6：验证与发布

1. 每次提交运行 `npx tsc --noEmit`、`npm run build`、算法回归脚本。
2. 使用 Playwright/CDP 验证 demo 页、真谱页、移动端和参数重分析。
3. 检查控制台无 worker、canvas、hydration 错误。
4. 记录识别指标、构建版本和部署时间，最后再重启 pm2 并检查 `/api/health`。
