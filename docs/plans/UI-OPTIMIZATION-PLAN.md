## 技术重点

### UI 优化原则
1. **一致性**: 统一的设计语言和交互模式
2. **响应式**: 适配不同设备和屏幕尺寸
3. **可访问性**: 符合 WCAG 标准
4. **性能**: 快速响应和流畅体验
5. **错误处理**: 清晰的错误提示和恢复路径

### Bug 修复原则
1. **重现**: 确保能够稳定重现问题
2. **隔离**: 找到问题的根本原因
3. **修复**: 实施最小化的修复
4. **测试**: 验证修复效果
5. **回归**: 确保没有引入新问题

### 代码质量标准
1. **TypeScript**: 完整的类型定义
2. **ESLint**: 通过所有 lint 检查
3. **格式化**: 统一的代码格式
4. **注释**: 清晰的代码注释
5. **测试**: 关键功能有测试覆盖

## 提交策略

遵循项目现有的提交风格：
- 简洁的祈使句标题（<72 字符）
- 详细的提交消息说明动机和影响
- 每个提交都是可独立审查的原子性改动
- 记录测试覆盖情况

提交分类：
- `fix:` - Bug 修复
- `feat:` - 新功能
- `refactor:` - 重构
- `style:` - 样式改进
- `docs:` - 文档更新
- `test:` - 测试相关
- `perf:` - 性能优化
