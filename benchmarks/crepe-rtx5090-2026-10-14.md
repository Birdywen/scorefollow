# CREPE full on RTX 5090: preliminary benchmark

## Environment and scope

- Windows RTX 5090, 32,607 MiB VRAM, driver 610.60.
- Isolated environment: `C:/Users/friend/crepe-5090`.
- Python 3.11.9, PyTorch 2.7.1+cu128, CUDA 12.8, torchcrepe 0.0.24.
- Full model, FP32, TF32 disabled; hop 128, 50–2000 Hz, batch size 1024.
- One resident model; crops still inferred and Viterbi-decoded independently.
- Linux analysis process sends PCM16-round-tripped crops through an SSH tunnel
  over Tailscale to a loopback-only temporary HTTP benchmark worker.
- Existing GPU workloads were left running (about 19.8 GB VRAM occupied before
  the benchmark). Production analysis was not switched to this worker.

## Fixed real-job replay

Input: persisted job `c11a832f58854a11b44bfa0b48c20982`, 82.098 seconds,
22,050 Hz WAV; original MusicXML and parameters (80 BPM, violin, start measure
1, vamp-beat, 25-cent tolerance). The unchanged engine still executed both
CREPE rounds, with 39 and 19 crops, respectively.

| Metric | CPU reference | RTX 5090 |
| --- | ---: | ---: |
| End-to-end analysis | 283.3–287.6 s offline; 304.738 s original service | 11.980 s |
| First CREPE round | 201.7 s in timed CPU reference | 2.191 s worker; 2.711 s including transport |
| Second CREPE round | 77.8 s in timed CPU reference | 0.916 s worker; 1.126 s including transport |
| Feature extraction | 1.7 s | 1.712 s |
| Peak PyTorch allocated GPU memory | N/A | 1,676.6 MiB |

GPU full-job performance assertions passed: total <20 s and CREPE worker time
<10 s, 246 output notes, unchanged rescue reasons `tempo, offset, range`.
This is one warmed offline replay, not a production latency percentile.

The first one-second crop after model load took 17.242 s inside the worker
(17.298 s wall); subsequent calls took 0.188 and 0.073 s inside the worker.
These first-request measurements exclude process/model startup. A production
worker must load and warm up before declaring readiness.

## Numerical checks and limitations

The unseeded full replay had three pitch classification changes compared with
the original CPU result, each crossing the 25-cent boundary:

| Note | Original CPU cents | GPU cents |
| --- | ---: | ---: |
| n98 | 24.3 | 25.5 |
| n134 | 23.6 | 25.7 |
| n230 | 24.4 | 29.2 |

Maximum pitch-error difference across comparable notes was 18.1 cents.
These results are not bit-identical and must not be advertised as zero
classification changes.

`torchcrepe.convert.dither` draws triangular random noise during conversion
from bins to cents, including on CPU. A separate fixed-seed comparison used
three one-second real crops starting at 20, 40 and 60 seconds, with the same
full-model parameters and identical seed for each CPU/GPU pair. All passed:

- Maximum frame pitch difference: 0.0006192 cents.
- Maximum periodicity difference: <0.0000021.
- All frame voicing gates at 0.5 agreed.

This supports FP32 CPU/GPU parity on those crops; it does not prove every
full-job difference arises from dithering or replace broader regression.
Neither scoring thresholds nor production randomness were changed.
